# QRPrint Offline Micro SaaS

QRPrint Offline is a Linux/Windows local-first print management starter for copy shops and merchant print counters. Customers scan the merchant QR code, upload documents, preview them, choose print preferences, enter contact details, select Cash or UPI, and receive a thank-you screen. Merchants manage only queue metadata and status, not direct customer file browsing.

## Quick start

```bash
git clone [repo]
cd QRPrint-offline-codex
npm install
npm run dev -- --host 127.0.0.1 --port 3000
```

## Guided merchant onboarding

- Windows: double-click or run `install-windows.bat`.
- Linux: run `chmod +x install-linux.sh && ./install-linux.sh`.

Both wizards collect shop name, owner, staff, printer count, default printer, address, mobile, email, local port, and the mandatory first-time front-page preference. At completion they display `http://127.0.0.1:[port]`.

## Production architecture

- **Frontend:** Vite + React + Tailwind CSS, responsive merchant and customer UIs.
- **Local data:** Browser localStorage demo adapter plus `data/merchant-profile.json` generated by installers. A production build should replace this with SQLite.
- **Suggested backend:** Node/Express bound to `127.0.0.1`, SQLite WAL, structured JSON logging, and OS print adapters for Windows Print Spooler and Linux CUPS.
- **Security:** localhost binding, customer file isolation, audit logs, validation, least-privilege printer access, future dashboard passcode/session middleware, and periodic document cleanup.

## API contract

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Local daemon health and version |
| GET/PUT | `/api/merchant-profile` | Installation profile |
| GET/PUT | `/api/settings` | Paper sizes, pricing, UPI, theme, accent |
| GET/POST | `/api/jobs` | Queue metadata and customer job creation |
| PATCH | `/api/jobs/:id/status` | Merchant queue status transition |
| GET | `/api/logs` | Audit and daemon logs |

## SQLite schema sketch

```sql
CREATE TABLE merchant_profile (id INTEGER PRIMARY KEY, shop_name TEXT NOT NULL, owner_name TEXT NOT NULL, address TEXT, mobile TEXT, email TEXT, port INTEGER NOT NULL, add_front_page INTEGER NOT NULL);
CREATE TABLE staff (id INTEGER PRIMARY KEY, name TEXT NOT NULL, active INTEGER NOT NULL DEFAULT 1);
CREATE TABLE printers (id INTEGER PRIMARY KEY, name TEXT NOT NULL, platform TEXT CHECK(platform IN ('windows','linux')), is_default INTEGER NOT NULL DEFAULT 0, status TEXT NOT NULL);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE print_jobs (id TEXT PRIMARY KEY, created_at TEXT NOT NULL, customer_json TEXT NOT NULL, file_manifest_json TEXT NOT NULL, preferences_json TEXT NOT NULL, payment_json TEXT NOT NULL, status TEXT NOT NULL, progress INTEGER NOT NULL DEFAULT 0);
CREATE TABLE audit_logs (id TEXT PRIMARY KEY, created_at TEXT NOT NULL, level TEXT NOT NULL, message TEXT NOT NULL);
```

## Merchant onboarding checklist

1. Clone the repository.
2. Run the OS-specific installer.
3. Confirm printers are installed at OS level.
4. Open the displayed localhost URL.
5. Edit paper sizes, page pricing, UPI ID, theme, accent color, and auto-spool preferences in the web dashboard.
6. Print the dashboard QR for customers.
